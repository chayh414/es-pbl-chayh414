## (개인·필수) 문제 1 — 사용자와 판단 하나로 좁히기

Dashboard를 사용할 사람 한 명과 그 사람이 내릴 판단 하나를 정하세요.

### 답안

- 내 주제: 빈티지·세컨핸드 의류 상품 검색
- 한 문서의 의미: 중고(빈티지·세컨핸드) 의류 상품 1건
- 사용자 한 명: 빈티지 마켓 운영자(판매자)
- 사용자가 반복해서 하는 일: 매일 새로 등록/판매된 상품 현황을 확인하고 다음 사입·가격 전략을 정함
- Dashboard를 보고 결정할 것: 어떤 카테고리·가격대·상태등급 상품을 더 확보하거나 가격을 조정할지
- 결정 뒤 수행할 행동: 재고가 적은 카테고리 위주로 사입하거나, 평균가가 낮은 카테고리의 프라이싱을 재검토
- 사용자에게 필요 없는 정보: 개별 상품의 세부 하자 설명 텍스트(defects 원문), 정확한 등록 시각(초 단위)

`모든 사용자`, `전체 현황`, `데이터를 본다`처럼 넓은 표현은 한 사람과 한 행동으로 좁힙니다.

## (개인·필수) 문제 2 — 서로 중복되지 않는 질문 4개

다음 역할을 하나씩 사용해 질문 4개를 작성하세요.

1. 전체 규모
2. 그룹 비교
3. 수치 분포 또는 정확한 값 비교
4. 상태 비율 또는 시간 변화

| 번호 | 분석 질문 | 질문의 답으로 내릴 판단 | 다른 질문과 겹치지 않는 이유 |
|---|---|---|---|
| Q1 | 전체 등록된 상품 수는 몇 개인가? | 전체 재고 규모 파악 (Metric) | 그룹·분포·상태 구분 없는 단일 총량 |
| Q2 | 카테고리별 평균 가격은 얼마인가? | 어느 카테고리가 프리미엄/저가인지 비교 | 그룹(category) 간 비교, 개별 값 분포가 아님 |
| Q3 | 가격은 어느 구간에 몰려 있는가? | 주력 가격대를 파악해 사입/프라이싱 조정 | 숫자 field(price)의 구간별 분포, 그룹 비교가 아님 |
| Q4 | 판매완료(sold) 비율은 어떠한가? | 재고 소진 속도·현재 판매 상태 파악 | 상태 비율, 앞의 그룹·수치 분포와 다른 boolean 상태 지표 |

## (개인·필수) 문제 3 — 질문별 field 존재 여부 점검

각 질문에 필요한 field가 실제 mapping과 문서에 있는지 확인하세요.

| 질문 | 필요한 field | mapping type | 실제 존재 | 값이 충분히 분포 | 가능/가공 필요/추가 필요 |
|---|---|---|---|---|---|
| Q1 | (없음, Records) | - | 존재 | 해당 없음 | 가능 |
| Q2 | category, price | keyword, integer | 존재 | 6개 카테고리에 고르게 분포(4교시에서 확인) | 가능 |
| Q3 | price | integer | 존재 | 5,000~150,000 범위 전체에 분포(생성 규칙 확인) | 가능 |
| Q4 | sold | boolean | 존재 | TrueRatio 0.30로 설계, 30% 근처로 분포 | 가능 |

- 현재 데이터로 바로 만들 수 있는 질문 수: 4개(전부)
- 선택한 A/B/C 경로: A (개인 데이터로 제작)
- 선택 이유: 4개 질문에 필요한 field가 이미 mapping과 실제 문서에 모두 존재하고 분포도 확인됐음

## (개인·필수) 문제 4 — 부족한 데이터 생성 규칙 설계

현재 답할 수 없는 질문 하나를 선택하고 필요한 데이터를 구체화하세요.

(필수 질문 4개는 모두 가능하여, 도전적인 5번째 질문을 가정해 답함: "브랜드별 재구매 고객 비율은 어떠한가?")

- 답할 수 없는 질문: 브랜드별 재구매 고객 비율은 어떠한가?
- 부족한 field: customer_id(고객 식별자), is_repeat_buyer(재구매 여부) — 현재 vintage-items는 상품 단위 문서라 고객·거래 단위 정보가 없음
- mapping type: customer_id=keyword, is_repeat_buyer=boolean
- 예시값 3개: customer_id 예 "CUST-00123", "CUST-00456", "CUST-00789"
- 범주라면 고유값 수: 해당 없음 (고객 수는 상품 수보다 적은 임의 규모로 설계 필요, 예: 1,000명)
- 수치라면 최소·최대·대표 구간: 해당 없음
- 상태라면 예상 비율: is_repeat_buyer는 재구매 고객 약 20~30% 가정
- 날짜라면 기간과 단위: 해당 없음
- 다른 field와 필요한 관계: 상품 문서와 별도로 "구매 이력" 문서(고객ID+상품ID+구매일)가 있어야 브랜드별 재구매율 계산 가능 — 현재 프로젝트 범위(상품 검색) 밖의 새로운 index 설계가 필요
- 한 문서를 생성하는 규칙: (설계만) 구매 이력 index를 새로 만들어 문서당 customer_id, purchased_brand, purchase_date를 기록하고, 고객별 구매 횟수를 집계해 재구매 여부 판단
- 필요한 문서 수와 이유: 최소 상품 판매 건수(sold=true인 약 1,500건) 이상 — 실제 판매 이력과 연결돼야 의미 있는 재구매율이 나옴
- seed 고정 여부: 고정 필요 (재현 가능성을 위해)
- 생성 후 검증 방법: 고객별 구매 건수 분포를 집계해 최소 2회 이상 구매한 고객 비율이 설계한 재구매율(20~30%)과 근사한지 확인

“랜덤으로 많이 만든다”는 규칙이 아닙니다. Dashboard에서 비교·분포·필터 결과가 나타나도록 값의 범위와 관계를 적습니다.
