# 7교시 실습 — 검색 품질 점검

## (공통) 문제 1 — 제공 코드로 상위 결과 평가

```http
GET /products/_search
{
  "size": 10,
  "query": {
    "multi_match": {
      "query": "무선 이어폰",
      "fields": ["name^3", "description"]
    }
  }
}
```

### 결과 입력

(이번 교시 6교시의 문제 3과 동일한 요청이라 그때 실행한 실제 결과를 그대로 사용함)

| 순위 | 문서 ID | name | 관련/보류/무관 | 근거 |
|---:|---|---|---|---|
| 1 | P-00241 | SoundLab 프리미엄 무선 이어폰 | 관련 | "무선 이어폰"이 상품명에 그대로 포함, boost로 score 최고(20.28) |
| 2 | P-00305 | Auralis 실속형 무선 이어폰 | 관련 | 동일하게 상품명에 "무선 이어폰" 정확히 포함 |
| 3 | P-00529 | NeoTech 스마트 무선 이어폰 | 관련 | 동일하게 상품명에 "무선 이어폰" 정확히 포함 |

- `hits.total.value`: 505
- 결과 수가 많다는 사실만으로 품질이 좋다고 말할 수 있는가: 아니오. 505건 중 상위권은 상품명에 "무선 이어폰"이 정확히 들어있어 관련성이 높지만, 총 505건에는 "무선 청소기"처럼 "무선"만 있고 "이어폰"과 무관한 상품도 섞여 있다(6교시 phrase 검색에서 249건만 "무선 이어폰"이 붙어있었던 것과 비교). 즉 건수가 많다고 상위 결과의 관련성이 보장되는 게 아니라, 실제 상위 몇 건을 사람이 직접 눈으로 확인해야 품질을 판단할 수 있다.

## (공통) 문제 2 — 정확 조건 품질 직접 구현

category가 `전자기기`이고 `in_stock=true`인 상품만 검색하는 API를 작성하세요. 최대 10건을 반환하고 모든 결과가 두 조건을 만족하는지 확인하세요.

### API 전체 입력

```http
GET /products/_search
{
  "size": 10,
  "query": {
    "bool": {
      "filter": [
        { "term": { "category": "전자기기" } },
        { "term": { "in_stock": true } }
      ]
    }
  }
}
```

### 결과 입력

- `hits.total.value`: 1065
- 기대 문서 ID·이유: P-00009(category=전자기기, in_stock=true), P-00025(동일 조건 만족) — 둘 다 두 조건을 실제로 만족해 결과에 포함되는 게 맞음
- 제외 문서 ID·이유: P-01409(6교시/이번 문제1에서 본 in_stock=false 문서) — 재고가 없어 이번 결과에는 나타나지 않아야 함
- 확인한 모든 문서가 조건을 통과했는가: 예. 상위 10건 전부 `_source.category`="전자기기", `_source.in_stock`=true. `max_score`도 0인데, filter만 사용해 점수 계산에 관여하는 조건이 없기 때문.

## (공통) 문제 3 — 의도한 0건 직접 구현

실제 `products` index와 실제 `product_id` field를 사용하되, 데이터에 존재하지 않는 값 `__DAY03_INTENTIONAL_ZERO__`를 검색해 정상적인 0건 요청을 구현하세요.

### API 전체 입력

```http
GET /products/_search
{
  "query": { "term": { "product_id": "__DAY03_INTENTIONAL_ZERO__" } }
}
```

### 결과 입력

- HTTP 성공 여부: 성공 (`_shards.failed`=0, `error` 필드 없음, `timed_out: false`)
- `hits.total.value`: 0
- index·field가 실제 존재한다는 근거: 요청 자체가 에러 없이 정상 처리됨(`_shards.successful: 3`). index나 field가 없었다면 `index_not_found_exception` 같은 오류가 났을 것.
- 값만 존재하지 않는다는 근거: `product_id`는 앞의 여러 문제(P-00009 등)에서 실제로 값이 있는 field로 이미 검증됐고, 이번엔 그 field에 존재하지 않는 임의 문자열(`__DAY03_INTENTIONAL_ZERO__`)을 넣었을 뿐이라 0건이 나오는 게 정상.
- 오류 0건과 정상 0건의 차이: 오류 0건은 요청 자체가 잘못돼(index/field명 오타, mapping과 안 맞는 타입 등) 응답에 `error` 필드가 있거나 예외가 발생하는 경우다. 정상 0건은 요청은 문법·구조 다 맞고 실행도 성공했지만, 조건에 맞는 데이터가 실제로 없어서 결과가 0건인 경우다. 이번 요청은 후자에 해당한다.

## (개인) 문제 4 — 자기 질문 3개 품질 점검

자기 PBL의 전문 검색, 정확 조건, bool/filter 질문을 각각 실행하고 기대 문서와 제외 문서를 판정하세요.

### 역할·검증 기준

- 질문마다 독립된 요청 ID를 사용합니다.
- 실행 전에 기대·제외 기준을 적습니다.
- 상위 3개를 실제 `_source`로 평가합니다.

### 결과 입력

(2·5·6교시에서 이미 실제로 실행한 요청을 재사용함 — 재현 요청은 개인 저장소 루트 `requests.http`에 있음)

| 질문 | 요청 ID | 기대 ID | 제외 ID | 상위 3개 | 판정·근거 |
|---|---|---|---|---|---|
| 전문 검색 ("설명에 데님이 언급된 상품") | `match description:"데님"` (2교시 문제5) | VI-00001 | VI-00002 | VI-00001, VI-00008, VI-00028 | 통과. total 759, 상위 3건 모두 description에 실제로 "데님" 포함. VI-00002는 description에 "데님" 언급 없어 제외돼야 하고, 실제로 결과에 없음. |
| 정확 조건 ("A급 상태 상품만") | `term condition:"A급"` (2교시 문제4) | VI-00001 | VI-00002 | VI-00001, VI-00003, VI-00010 | 통과. total 1691, 상위 3건 모두 condition="A급". VI-00002는 condition="B급"이라 제외돼야 하고 실제로 결과에 없음. |
| bool/filter (Q1: "3만원 이하 A급 데님 자켓") | `bool must+filter×4` (5교시 문제4) | VI-00001 | VI-00002 | VI-00001, VI-00531, VI-01076 | 통과. total 14, VI-00001이 최고 점수(진짜 "데님 자켓"). VI-00002는 category="하의"·condition="B급"으로 filter 2개 위반이라 제외돼야 하고 실제로 결과에 없음. |

## (개인) 문제 5 — 실패 원인 진단

개인 문제 4에서 실패·보류 또는 개선 여지가 있는 결과 하나를 선택해 원인을 진단하세요.

### 역할·검증 기준

- mapping / analyzer / query / filter / sort / data 중 1차 원인을 선택합니다.
- 실제 mapping·문서·응답 근거를 하나 이상 첨부합니다.
- 아직 요청을 고치지 말고 원인과 다음 실험을 분리합니다.

### 진단 입력

- 문제: bool/filter(Q1) 결과에 VI-00531("Dickies 2000s 데님 아우터")처럼 "자켓"이 아니라 "아우터"인 문서가 섞여 나옴. 사용자는 "자켓"을 검색했는데 카테고리성 단어인 "아우터"에도 매칭된 것은 관련성이 떨어짐.
- 1차 원인: query — `match`의 기본 `operator`가 `"or"`라서 "데님 자켓"을 "데님" OR "자켓"으로 나눠 찾음. item_name에 "데님"만 있어도(즉 "자켓"이 없어도) 매칭이 되어버림.
- 확인한 실제 근거: 5교시 문제4 실제 응답에서 VI-00531의 score가 1.9389737로, "데님 자켓"이 그대로 있는 VI-00001의 score(8.88765)보다 훨씬 낮지만 어쨌든 `hits`에 포함되어 total 14건에 들어갔음. VI-00531의 item_name엔 "자켓"이라는 단어가 아예 없고 "아우터"만 있음.
- 다음에 바꿀 한 요소: `match`에 `"operator": "and"`를 추가하거나 `match_phrase`로 바꿔서, "데님"과 "자켓"이 둘 다(또는 순서대로 붙어서) 있는 문서만 걸러지는지 다음 단계에서 실험할 것.
- 새 Console 재현 여부: 아직 안 함 (이번 문제는 원인 진단까지만, 요청 수정·재실행은 8교시 통합·개선 단계에서 진행)
