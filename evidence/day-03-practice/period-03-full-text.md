# 3교시 실습 — 전문 검색 확장

## (공통) 문제 1 — 제공 코드로 여러 field 검색

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "무선 이어폰",
      "fields": ["name", "description"]
    }
  }
}
```

### 결과 입력

- `hits.total.value`: 505
- 상위 3개 ID·name: P-00241(SoundLab 프리미엄 무선 이어폰), P-00305(Auralis 실속형 무선 이어폰), P-00529(NeoTech 스마트 무선 이어폰)
- 각 문서가 name·description 중 어디에서 의도와 연결되는가: 상위 3건 전부 `name`에 "무선"과 "이어폰"이 둘 다 포함돼 있어 두 단어 모두 name field에서 매칭됨. `description`은 "재택 학습에 잘 어울리는 전자기기 상품입니다"처럼 정형화된 문구라 "무선"/"이어폰" 단어를 포함하지 않음.
- 상위 3개 관련/보류/무관 판정: 3건 모두 관련 (실제로 무선 이어폰 상품이며 검색 의도와 정확히 일치)

## (공통) 문제 2 — field boost 직접 구현

문제 1과 같은 조건을 유지하되 `name` 일치를 `description`보다 3배 중요하게 보는 Search API를 작성하세요.

### API 전체 입력

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "무선 이어폰",
      "fields": ["name^3", "description"]
    }
  }
}
```

### 비교 결과

- 변경 전 상위 3개 ID: P-00241, P-00305, P-00529 (max_score 6.7587247)
- 변경 후 상위 3개 ID: P-00241, P-00305, P-00529 (max_score 20.276176, 동일 순서)
- 순위가 달라진 문서와 이유: 순위 변화 없음. 상위 5건이 이미 전부 `name`에서 매칭돼 가장 높은 점수를 받고 있었기 때문에, name에 boost(`^3`)를 줘도 같은 문서들이 똑같이 3배 가까이(6.76→20.28) 점수가 오르기만 하고 순위는 그대로였다.
- boost가 사용자 의도에 유리했는가: 이번 케이스에서는 순위엔 영향이 없었지만, 만약 description에서만 "무선"이 언급되고 name엔 없는 문서가 상위권에 있었다면 boost로 인해 name 매칭 문서에게 순위가 밀렸을 것이다. 즉 "상품명에 검색어가 있는 게 더 중요하다"는 의도를 명확히 반영하는 장치이며, 지금 데이터에서는 우연히 순위 변화가 없었을 뿐 boost 자체는 의도대로 작동했다.

## (공통) 문제 3 — 구문 검색 직접 구현

`products` index의 `name`에서 `무선 이어폰`이라는 단어 순서와 인접성을 중요하게 검색하세요. `slop`은 0, 최대 5건으로 구현하세요.

### API 전체 입력

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "match_phrase": {
      "name": {
        "query": "무선 이어폰",
        "slop": 0
      }
    }
  }
}
```

### 결과 입력

- `hits.total.value`: 249
- 상위 문서 ID·name: P-00241(SoundLab 프리미엄 무선 이어폰), P-00305(Auralis 실속형 무선 이어폰), P-00529(NeoTech 스마트 무선 이어폰)
- 문제 1보다 결과가 같거나 줄어든 이유: 249로 줄어듦(문제1은 505). `match_phrase`는 "무선"과 "이어폰"이 순서대로 바로 붙어있는 문서만 찾기 때문에, "무선 청소기"처럼 "무선"만 있고 "이어폰"이 없거나 순서가 다르거나 사이에 다른 단어가 낀 문서는 전부 제외된다.
- 구문 의도에 맞지 않는 문서가 있는가: 없음. 상위 5건 전부 name에 "무선 이어폰"이 정확히 붙어서 등장하며, "무선 청소기"(문제 2에 있던 CleanMate 상품 등)처럼 구문과 안 맞는 상품은 이 결과에서 빠졌음을 확인함.

## (개인) 문제 4 — 여러 text field 검색

자기 프로젝트에서 같은 사용자 검색어가 적용될 수 있는 text field 2개 이상을 선택해 전문 검색을 구현하세요.

### 역할·검증 기준

- 각 field의 서비스 역할을 설명합니다.
- 상위 3개 문서를 사람이 평가합니다.
- 한 field만 필요한 도메인이라면 `match`를 선택하고 그 이유를 적어도 됩니다.

### API와 결과 입력

```http
GET /vintage-items/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "데님 자켓",
      "fields": ["item_name", "description"]
    }
  }
}
```

- 사용자 질문·검색어: "데님 자켓을 찾고 싶다" / "데님 자켓"
- 선택 field와 역할: item_name(제목, 상품명에 검색어가 직접 있으면 가장 관련성 높음), description(상세 설명, 제목에 없어도 본문에 소재·특징이 언급될 수 있음)
- 상위 3개 판정: VI-00001(관련 — item_name·description 둘 다 "데님 자켓" 그대로 포함, score 9.99로 최고점), VI-00003(보류 — "자켓"만 일치하고 소재는 나일론이라 데님이 아님, score 7.82로 2위), VI-00008(무관 — "데님"은 있지만 원피스이지 자켓이 아님, score 1.94로 급감)
- query 선택 근거: `multi_match`를 사용해 item_name·description 둘 중 어디에 있어도 찾되, 기본적으로 두 단어("데님", "자켓")를 모두 포함한 문서(VI-00001)가 하나만 포함한 문서보다 훨씬 높은 점수를 받도록 함. 정확 조건이 아니라 "얼마나 의도에 가까운가"를 점수로 구분해야 하는 상황이라 term이 아닌 전문 검색이 적합했음.

## (개인) 문제 5 — boost 또는 phrase 가설 검증

자기 검색에서 field boost 또는 phrase 중 하나를 선택해 기본 요청과 비교하세요.

### 역할·검증 기준

- 같은 index·데이터·검색어·size를 유지합니다.
- 한 요소만 변경합니다.
- 결과가 바뀌지 않아도 실제 결과대로 기록합니다.

### API와 결과 입력

```http
GET /vintage-items/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "데님 자켓",
      "fields": ["item_name^3", "description"]
    }
  }
}
```

- 선택한 가설: boost — item_name을 description보다 3배 중요하게 취급하면, 이미 item_name에서 매칭된 상위 문서들의 점수가 더 뚜렷하게 벌어질 것이다.
- 변경 전·후 상위 3개: 변경 전 VI-00001(9.99)/VI-00003(7.82)/VI-00008(1.94) → 변경 후 VI-00001(26.66)/VI-00003(23.46)/VI-00008(5.82), ID 순서는 동일
- 개선/보류/악화 판정: 보류 (순위 자체는 안 바뀜)
- 판정 근거: 이번 검색어·데이터에서는 이미 item_name 매칭 문서가 자연스럽게 상위였기 때문에 boost를 줘도 순서가 바뀌지 않았다. 다만 점수 차이는 커져서(1·2위 격차 2.17→3.20, 2·3위 격차 5.88→17.64) description에만 검색어가 있는 문서가 상위로 치고 올라올 여지가 이전보다 더 줄어들었다 — 즉 순위엔 변화가 없지만 "제목 우선"이라는 의도는 이전보다 더 확실하게 반영됐다.
